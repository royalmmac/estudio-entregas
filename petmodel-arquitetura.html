Plano de Arquitetura Definitiva & Consolidação Técnica (Lovable ↔ Supabase)

Este documento consolida a estrutura relacional definitiva no Supabase (PostgreSQL + RLS + Storage), o mapeamento de dependências com o frontend gerado no Lovable (React/Vite/Tailwind) hospedado na Vercel e o protocolo seguro de migração dos ~2.000 perfis ativos do sistema legado em PHP/MySQL sem perda de mídias, vínculos de tutores ou quebras de layout.

Módulo / Requisito Funcional Risco Comum no Lovable Solução Definitiva Antes da Migração Criticidade
1. Relação Tutor (1:N) Múltiplos Pets Frontend no Lovable frequentemente vincula campos do animal direto na tabela de perfil único do usuário. Separação estrita entre public.tutors (vinculado a auth.users) e public.pets (chave estrangeira tutor_id), permitindo N animais por conta com seleção rápida no painel do tutor. BLOQUEANTE P/ MIGRAÇÃO
2. Campos por Espécie, Raça Padronizada e Comportamento Campos livres em texto geram inconsistência nos filtros de casting ("Golden", "Golden Retriever", "golden"). Tabela normalizada species_breeds + JSONB tipado physical_traits (cor pelagem, olhos, peso, porte, medidas) + array indexado GIN para temperamento e sociabilidade entre espécies. BLOQUEANTE P/ MIGRAÇÃO
3. Habilidades (Comandos) com Vídeos + Fotos Categorizadas Upload direto sem políticas de bucket no Supabase Storage ou URLs antigas quebradas do WordPress/PHP. Buckets separados (pet-photos e pet-skill-videos) com tabela pet_media categorizada (Perfil, Corpo Inteiro, Ação, Estúdio) e coluna legacy_mysql_id para reconciliação. BLOQUEANTE P/ MIGRAÇÃO
4. Influência Digital & Privacidade (RLS) Exposição pública no frontend de dados sensíveis do tutor (telefone, CPF, endereço, métricas privadas). View pública filtrada (public_casting_catalog) + Row Level Security (RLS) garantindo que apenas role = 'admin' (equipe Pet Model Brasil) e o próprio tutor leiam dados de contato. CRÍTICO (LGPD)
5. Planos, Assinaturas Stripe & Lembretes Webhook do Stripe processado no cliente ou desatualizado após renovação/cancelamento. Supabase Edge Function stripe-webhook sincronizando subscriptions + Cron Job (pg_cron) disparando alerta de atualização cadastral a cada 90 dias (especialmente filhotes). PRONTO NO SCHEMA

CREATE TYPE user_role AS ENUM ('tutor', 'admin', 'casting_producer');
CREATE TYPE pet_species AS ENUM ('dog', 'cat', 'exotic', 'bird', 'equine', 'other');
CREATE TYPE media_category AS ENUM ('headshot', 'full_body', 'side_profile', 'action', 'skill_video', 'studio');

-- 1. TABELA DE TUTORES (1 Tutor -> N Pets)
CREATE TABLE public.tutors (
  id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  legacy_user_id INT UNIQUE, -- ID original no sistema PHP/MySQL para rastreabilidade
  role user_role NOT NULL DEFAULT 'tutor',
  full_name TEXT NOT NULL,
  cpf_cnpj TEXT,
  phone_whatsapp TEXT NOT NULL,
  city TEXT NOT NULL,
  state CHAR(2) NOT NULL,
  zip_code TEXT,
  terms_accepted_at TIMESTAMPTZ,
  terms_version TEXT DEFAULT '2026-v1',
  stripe_customer_id TEXT UNIQUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 2. CATÁLOGO PADRONIZADO DE ESPÉCIES E RAÇAS (Evita duplicidade no filtro de Casting)
CREATE TABLE public.species_breeds (
  id SERIAL PRIMARY KEY,
  species pet_species NOT NULL,
  breed_name TEXT NOT NULL,
  slug TEXT UNIQUE NOT NULL
);

-- 3. TABELA PRINCIPAL DE PETS ( Amostra parcial na prévia de homologação )

  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tutor_id UUID NOT NULL REFERENCES public.tutors(id) ON DELETE CASCADE,
  legacy_pet_id INT UNIQUE,
  name TEXT NOT NULL,
  species pet_species NOT NULL,
  /* ... [CAMPOS DE CASTING, JSONB PHYSICAL_TRAITS E ÍNDICES GIN OMITIDOS NA PRÉVIA] ... */

03 · MAPA DE DEPENDÊNCIAS (LOVABLE · GITHUB · SUPABASE · VERCEL) & PLANO DE TESTES Zero Perda de Dados · Rollback Seguro

Fluxo de Sincronização Sem Quebrar o Lovable

Como o Lovable sincroniza via repositório GitHub em commits bidirecionais, qualquer alteração estrutural deve respeitar esta ordem:

  1. Congelamento de Schema no Supabase: Aplicar as migrations SQL acima e gerar os tipos TypeScript (supabase gen types typescript) commitando em src/integrations/supabase/types.ts.
  2. Variáveis na Vercel: Validar VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY e configurar os Secrets do Stripe (STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET) exclusivamente nas Edge Functions do Supabase.
  3. Dry-Run de Migração (Lote Piloto de 50 Perfis): Script Node.js lê o dump MySQL antigo, higieniza telefones/raças, copia as fotos de wp-content/uploads para o Supabase Storage e preenche legacy_pet_id.

Critérios de Aceite (Homologação Antes da Virada)

  • Teste 01 (Multi-Pet por Tutor): Criar 1 tutor e cadastrar 1 cão + 1 gato + 1 ave com campos específicos de cada espécie sem colisão de estado.
  • Teste 02 (Upload de Vídeo de Habilidade): Subir vídeo MP4/MOV de até 50MB atrelado a uma habilidade específica e reproduzir no painel Admin de Casting.
  • Teste 03 (Auditoria RLS / Privacidade): Garantir que uma requisição anônima à API do Supabase retorne apenas nome artístico, fotos e medidas do pet, ocultando 100% do telefone, CPF e endereço do tutor.
  • Teste 04 (Batimento 2.000 Perfis): SELECT COUNT(*) FROM pets WHERE legacy_pet_id IS NOT NULL idêntico ao total ativo no MySQL legado.
